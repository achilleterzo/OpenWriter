# src/App.jsx

Source: [`src/App.jsx`](../../../src/App.jsx)

Root component and workspace state holder: tabs, active document, project, side panel (`sideTab`), expanded folders, assistant panel, conversation, chat context pins, notes, bookmarks, find requests, context menu, layout, and the settings screen (opened by the app menu or after a language change).

- Builds the tab model: untitled documents, opened files (only Markdown saves in place; DOCX and PDF become new documents keeping the original as `sourcePath`), browser tabs (`kind: 'browser'`), and image tabs (`kind: 'image'`, opened from the explorer and shown by [ImagePane.jsx](components/pages/ImagePane.jsx.md)). Browser and image tabs carry no editor or session state. Document tabs keep `untitled` counters, and a tab opened by a single click is a preview (`preview`) that the next opened file replaces, until the user works on it or double-clicks to keep it.
- Persists and restores the per-project session: open tabs (drafts kept in the session for dirty or never-saved tabs; other documents reopened from disk), active id, side tab, expanded folders, assistant state, chat context pins, and the active conversation. The assistant edits still to review are saved per tab through [pendingChangesExtension.js](lib/pendingChangesExtension.js.md) and restored on reopening. Older sessions with embedded chat are imported once into `.ow/chat`.
- Executes workspace actions: new/open/close tabs, saving every modified document at once (`Save all` in the tab bar), path rename and delete remapping across tabs (a deleted file keeps its tab open as unsaved text), find and replace requests (Ctrl+F / Ctrl+H), browser and image tabs, titles, and dirty/save bookkeeping.
- Projects: switch (saving the session first), open, create, move, and the projects view when no project is open; the preferences (theme, language, panel widths) are read and written through [preferences.js](lib/preferences.js.md) and [appearance.js](appearance.js.md).
- Tool bridge for the assistant: live editor text of open documents (including unsaved changes), the list of the documents with unsaved changes and their text (`getDirtyDocuments`, which the MCP server's search uses through the bridge instead of the older files on disk), bookmarks (setting them in the text and opening the flagged ones), `list_versions`/`read_version`, memory operations (`remember`, `recall`, …), browser tab listing/selection, document, image and browser screenshots, automatic "Before the AI edit" version snapshots, note and bookmark change events, path change events (delete/rename refresh tabs and explorer), and opened-file opening.
- Note and bookmark integration: loads the notes and bookmarks of the context document, highlights them in the editor through the annotation and bookmark extensions, selects them (opening the corresponding side tab), and forwards "ask AI" requests from a note or a bookmark to the chat panel. A passage to discuss (from the selection bar, or from the right-click menu on text selected in the document, which adds "Discuss with AI in a new chat / in the current chat") opens the assistant and reaches the chat as a `passage` request.
- The AI-likelihood check asked from the toolbar is kept per tab (`aiScore`), with the score, the confidence and the rationale.
- Link handling: Ctrl+click opens project files in a tab, external links in the system browser, and explains unresolved relative links; a `#fragment` reaches the bookmark or the heading it names ([bookmarkLinks.js](lib/bookmarkLinks.js.md)).
- External agents: the requests of the MCP server forwarded by the main process are run through [mcpRequests.js](lib/mcpRequests.js.md) and answered to the bridge. Besides the editor edits and `read_open_document`, this is where an agent opens a document in a tab (`open_document`), switches the application to another project (`open_project`, through the same project switching the app uses, which saves the current session first), and hands a task to the assistant (`ask_agent`, which opens the assistant panel and sends the prompt as a user request, in a new chat or in the current one, with a label naming the agent that sent it and the message marked as coming through MCP rather than from the user). The request resolves once the message is saved, answering with the chat id and the index of the message — the agent follows the work through the server's `list_chats` / `read_chat` — and after a minute without the assistant starting it says so.
- Updates: the check can run at startup and then on a schedule chosen in the settings ([updateSchedule.js](lib/updateSchedule.js.md)), and a known release is reported by the update button of the rail.
- Side panels: besides the explorer, notes, bookmarks, history and web references, the `anchors` side tab shows the HTML anchors of the document ([AnchorsPanel.jsx](components/pages/AnchorsPanel.jsx.md)) and jumps to the one chosen, remembering the place first.
- Notices: `installDiagnostics` of [toasts.js](lib/toasts.js.md) is called once at startup and `onAppNotice` feeds the notifications of the main process, so errors and warnings of either process reach the same stack ([ToastHost.jsx](components/pages/ToastHost.jsx.md)) instead of only the terminal.
- Layout: left side panel and assistant panel widths are clamped and committed to `lib/layout.js`, with a status bar showing the project, the progress of the search index ([IndexProgress.jsx](components/pages/IndexProgress.jsx.md)) and the last status message.

**Home as a mode.** The projects Home (network and search) is a mode of the central area (`homeMode`), not of the side panel: choosing the Projects tab enters it and choosing any other tab leaves it, while collapsing the side panel does not change it, so the Home stays full screen with the panel closed, just as a document stays with the file panel collapsed. Choosing Projects again reopens the panel with the list. The mode is not saved between runs: after a restart the central area shows the document (a collapsed panel is restored as collapsed).

**Text tabs.** A file that is not a document (not `.md`, `.markdown`, `.mdown`, `.docx`, `.pdf`, nor an image) opens in a tab of `kind: 'text'` ([TextPane.jsx](components/pages/TextPane.jsx.md)): `workspace.openText` reads it, `openTextFile` creates the tab (or returns to the one already open), `saveText` writes it. It is not a document: `isDocument` excludes it, so it has no editor, notes, history or assistant context. Its text lives in the pane and is asked for through the registry `textBuffers`. The session keeps a `texts` list (path, position, and the draft if there are unsaved changes), restored like the browser tabs; renaming or deleting a file follows the tab; close, "Save all" and the Save menu command handle it. `openFromExplorer` sends such files to the text reader unless `asDocument` is passed: the assistant and the agents (`toolBridge.openFile`) open them as documents, as before. The File → Open dialog hands a file that is not a document to `openLoaded` with `format: 'text'`.

**Workspaces.** A folder passed from outside (file manager, command line, second launch) is opened after asking where to add it, when a workspace is active and the project is not one of its members: the current workspace (the default), another one (it adds the project and switches to it) or none (it stays only in All; closing the dialog counts as none). The project is opened with `join: false` so that the main process does not add it by itself. A change of the workspaces bumps `projectsVersion`, so the Home reads the graph again. `openProject(directory, options)` passes `options` on.
