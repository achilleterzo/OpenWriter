# FileExplorer.jsx

Source: [`src/components/FileExplorer.jsx`](../../../../../src/components/FileExplorer.jsx)

Project file tree. Without a project it shows a placeholder with the button that opens a folder.

- Header: the project avatar and name (clicking it opens the folder in the file manager) and the buttons for a new folder, a new document, adding a reference folder, moving a project here, refreshing, and opening the project settings in a window ([ProjectSettingsDialog.jsx](ProjectSettingsDialog.jsx.md), usable for the open project and for a sub-project). A new folder or document is created in the folder last clicked (the header name shows which one) or in the project root.
- The tree lists folders, documents and images, loads a folder's children when it is expanded, and marks the project root, sub-projects (with their own icon) and empty folders. A document imported from DOCX or PDF shows its original file underneath, read-only and with a lock icon, opened on request.
- Keyboard works as in a file manager: the arrows move between the visible rows, Home and End go to the extremes, the right arrow opens a folder (or steps into its content) and the left one closes it (or returns to the folder containing the row). F2 renames, Delete deletes (with confirmation). With an image open, moving over another image shows it in the same tab without taking the focus away from the tree.
- A single click opens a file as a preview, a double click keeps the tab open ([TabBar.jsx](TabBar.jsx.md)); a document name keeps `.md` when the extension is omitted. Renaming and creating happen in line, in the folder concerned (Enter confirms, Escape cancels, losing focus confirms the rename and cancels the creation), and after a rename the focus returns to the moved row. Renaming a document renames its originals too.
- Context menu: open, new folder, new document, create sub-project, sub-project settings, open as project, make standalone project, move a project here, copy (Ctrl+C), cut (Ctrl+X), paste (Ctrl+V), rename, delete, reveal in the file manager (with the name the operating system uses).
- The file clipboard is the system one ([file-clipboard.cjs](../../../electron/file-clipboard.cjs.md)): files copied or cut here can be pasted in the file manager or in another program, and the other way round. Pasting reports how many files were copied, moved or skipped, and a cut from outside the project is copied rather than moved.
- Dragging a row hands the file to the system, so it can be dropped in another application; files dropped onto the tree are copied into the folder under the pointer (or into the project root), while items coming from the project itself are moved, with their history, notes, bookmarks and memory entries, and an original follows its Markdown. Folders work like files: a folder dropped from outside is copied with all its content (except `.ow`, `.git` and `node_modules`, and never into itself), and a folder dragged inside the tree is moved even when the system does not hand its path over with the dropped items, because the tree remembers what it started dragging until the mouse moves again.
- **Multiple selection**: Ctrl/Cmd+click adds or removes a row, Shift+click (or Shift+arrows) selects the range between the last clicked row and this one, Ctrl/Cmd+A selects everything visible, Esc clears; a plain click or an arrow selects that row alone. A modified click only changes the selection (it neither opens nor expands). Dragging a selected row drags the whole selection (one inside a selected folder follows the folder); dragging a row outside it drags that row alone. The context menu on a selected row acts on the whole selection (copy, cut, delete), with one confirmation for all; the keys Ctrl+C, Ctrl+X and Del do the same. Rename stays on a single item.
- A **References** section lists the folders outside the project that the assistant may only read ([project-references.cjs](../../../electron/project-references.cjs.md)), shown as `@name` with a lock; a missing folder can be relinked, and the context menu of a reference can reveal it, relink it or remove it (the folder is not touched).
- A **Linked documents** section lists the Markdown files linked from outside the project ([project-links.cjs](../../../electron/project-links.cjs.md)), opened and edited where they are: the context menu can open them, update a link that points to a missing file, reveal it, or unlink it (the file is not touched).
