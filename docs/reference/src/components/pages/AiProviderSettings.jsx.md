# AiProviderSettings.jsx

Source: [`src/components/AiProviderSettings.jsx`](../../../../../src/components/AiProviderSettings.jsx)

Settings screen section for the AI assistant: an enable switch and the choice among Ollama (local or remote HTTP service), Ollama Cloud (hosted API with an API key), OpenRouter (hundreds of models with one API key), Codex (CLI with ChatGPT OAuth), Claude (CLI with Claude OAuth), Gemini (Google AI Studio API key), and OpenAI-compatible (LM Studio, llama.cpp, vLLM, Groq, OpenAI and others), each with its logo and a one-line description. The cards are not defined here: they are [ProviderCards.jsx](ProviderCards.jsx.md), which also exports the `providers` list, the same one this section filters with `RESEARCH_PROVIDERS` for the research model.

Every OpenAI-compatible server the user adds is a card of its own (id `openai-<code>`, with its name, its address as description and its own icon): the "+" menu has an "OpenAI-compatible" entry that creates a new one (the first, `openai`, is taken back if it was hidden), and removing any server, the first included, deletes its settings after a confirmation in the app's own dialog ([Dialogs.jsx](Dialogs.jsx.md), `useDialogs().confirm`, with a single question and a red Remove button; the saved key stays; the first server cannot vanish from the settings, so it comes back empty when added again), while the other providers are only hidden. Up to 20 servers. A server without a model is not yet configured: its models are not asked for when it is chosen, only when the user presses Connect (or Enter in the address field), so that a new server does not fail against the default address before it has been set up; a server that already has a model is checked as soon as it is chosen.

The cards show only the providers the user has added (`activeProviders`, plus the chosen one even when a project picked another): a "+" next to the title opens a menu with the others, and adding one also chooses it so that it can be set up at once; a cross on the other cards removes them from the list, which only hides them (their settings and keys stay). The custom provider (OpenAI-compatible) can have a custom icon (`providerIcons`, a computer setting; the other providers keep their logo): an image the user picks is scaled by [providerIcon.js](../../lib/providerIcon.js.md) and saved in the settings, and a button restores the logo. The research provider list is limited in the same way.

For the chosen provider it shows: the endpoint with the connect button for Ollama and Ollama Cloud, and the model (through [ModelPicker.jsx](ModelPicker.jsx.md), which filters by accepted input); the token/API key field for Ollama (optional, with a hint), Ollama Cloud, OpenRouter, and Gemini — with a warning when a token is set for an `http://` endpoint that is not on this computer — with the "(saved)" flag, the link to create a key (for the hosted presets of the OpenAI-compatible provider it comes from the preset) and the button that saves or removes it from the encrypted storage; the sign-in state, the Check button and the OAuth flow for the CLI providers, including the authorization code to paste and the link to reopen the browser. The remaining settings are the reasoning effort (from [aiOptions.js](../../lib/aiOptions.js.md)), the reasoning of the steps that follow a tool result (`toolReasoning`: as configured, reduced to "low" — the default — or off), the assistant language, the generation parameters ([ParameterSlider.jsx](ParameterSlider.jsx.md): temperature, context and predicted tokens, keep-alive; the Codex sandbox for Codex), the tool-chain limit, and the toggles of the assistant tool groups, rendered from `toolOptions` ([toolOptions.js](../../lib/toolOptions.js.md)) — project files, creating files and folders, memory, notes in the document, editing the open document, questions with choices, images and screenshots, web browsing — each with its explanation. The same list is shown, with the same labels, in the settings of a single project, where each group can be set aside ([ProjectSettings.jsx](ProjectSettings.jsx.md)).

A **Research assistant** fieldset turns on the second model the assistant delegates explorations to ([researchAgent.js](../../lib/researchAgent.js.md)): a single switch, "Delegate the research to another dedicated assistant" (it searches and reads the project files on its own, never changes anything, and returns a short report), then its provider — only the ones with native tool calls (`RESEARCH_PROVIDERS`: Ollama, Ollama Cloud, OpenRouter, Gemini, OpenAI-compatible) — its model, chosen with [ModelPicker.jsx](ModelPicker.jsx.md) and its own list of models, and its step limit (4–30).

Images and screenshots are enabled only when the chosen model can read images: the component asks for the provider capabilities and warns when they are missing. For the OpenAI-compatible provider the section adds a service menu (the presets come from `ai.getPresets()`, which the main process answers from [provider-descriptors.cjs](../../../electron/provider-descriptors.cjs.md)), the server address (filled with the preset's address on every change of service, empty for the custom one), the token field (a key when the preset requires it, optional otherwise) and a name field (shown on the card, in the add menu, in the research provider list and in the chat; the service's name when empty) and two selects, "The model reads images" and "The model uses tools", each Automatic / Yes / No, with the value the server reported next to Automatic when it did, plus the reasoning level only when the service takes one. Service, address and the two switches are settings of the computer, not of a project. The saved-key flag is read again after each change of service or address, once the settings have been saved, because the key belongs to that service and address. Saving the settings goes through the AI settings IPC, and errors are shown in the section.
