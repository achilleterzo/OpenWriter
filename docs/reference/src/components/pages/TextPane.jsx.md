
# TextPane.jsx

Source: [`src/components/TextPane.jsx`](../../../../../src/components/TextPane.jsx)

The text reader: a tab for any file that is not a document (code, configuration, logs, `.txt`…), read and edited as it is, never interpreted as Markdown. It reuses the field of the Markdown source view ([SourceEditor.jsx](SourceEditor.jsx.md)).

- **Bar:** file name, lines and size; the buttons for the **Unicode text style** menu, **line numbers** (on or off, remembered in `localStorage`, shared by all text tabs), **find and replace**, **save**, and show in the file manager. The line ending and the encoding are in the status bar of the window ([TextFormatStatus.jsx](TextFormatStatus.jsx.md)); changing them counts as a modification even if the text is the same: the pane compares `eol` and `bom` of the tab with `savedEol` and `savedBom` and reports the file as modified or clean again.
- **Unicode text style** (the "Aa" button, disabled on a read-only tab): a menu of the styles of [unicode-text.cjs](../../../electron/unicode-text.cjs.md) — bold, italic, bold italic, monospace, underline and strikethrough first, then the serif ones, script, fraktur, double-struck, circled, fullwidth, small capitals and the squared ones — each with a sample on the right, "Remove the style", "Convert Markdown to formatted text", "Convert formatted text to Markdown" and a switch "Style accented letters too (may not display well)" — off by default, so accented letters stay normal, because the combining accent on a styled letter is drawn badly by many programs — remembered in the preference `openwriter.unicodeAccents` (`combine` or `keep`). A style applies to the selection and asks for one when there is none; applying a style to text that already has one switches directly to the new style (the same style twice removes it, underline and strikethrough add up), and the field keeps its selection and its focus while the menu is open (the button does not take the focus); removing the style and the two conversions work on the selection or, with none, on the whole file. The result replaces the text as if it were typed (`replaceInTextarea` in [textFormat.js](../../lib/textFormat.js.md), through `execCommand('insertText')`), so Ctrl+Z undoes it; the status line says "Converted" or, when something could not be carried over (heading levels, tables, images, HTML…), what. The calls go to the main process through `electronAPI.textFormat`.
- **Find and replace** (Ctrl+F, Ctrl+H, or the button): the same bar as the documents ([FindPanel.jsx](FindPanel.jsx.md)) with match case, whole word, and regular expression, driven by [TextFindBar.jsx](TextFindBar.jsx.md) and [textSearch.js](../../lib/textSearch.js.md). The matches are highlighted behind the field and the current one is brought into view; with a regular expression the replacement accepts `$1`, `$&`, `$<name>`.
- **State:** the text lives in the field. The application asks for it (`getText`, through a registry in `App.jsx`) to save and to keep a draft in the session; it receives only the passages from clean to modified (`onDirty`, `onClean`). The tab is mounted as long as it is open, like the images.
- **Saving:** Ctrl+S (or the button) writes the file with its own line endings and signature ([text-file.cjs](../../../electron/text-file.cjs.md)); "Save as…" asks where. Unsaved changes are asked about when closing, listed by "Save all", and kept in the session as a draft.

Limits: a file over 1 MB or not in UTF-8 is not opened (the reason is shown); the assistant and the agents do not see these tabs (they work on documents: for them a file is opened as a document, see `asDocument` in `openFromExplorer`).
