# AiChatPanel.jsx

Source: [`src/components/AiChatPanel.jsx`](../../../../../src/components/AiChatPanel.jsx)

Assistant side panel. Largest UI component of the app.

- Conversation threads: list with the parent branch marked, create, rename, delete, open the `.ow/chat` folder, and branching (`parentId`, `branchedAt`, and `contextFrom` links to previous conversations used as context, added or removed as chips). Editing a previous message removes the replies after it.
- Message composer with the context documents (the active one included automatically, the others pinned or not), image and PDF attachments, and the quick actions (the project's own first, then the general ones — by default proofread, rewrite, summarize, lengthen, review — see [quickActions.js](../../lib/quickActions.js.md)) followed by the actions of the active skills.
- Passages under discussion: a passage selected in the document (from [SelectionToolbar.jsx](SelectionToolbar.jsx.md)) is attached to a new or the current conversation as a chip (× removes it) and saved with it (`passages`). While a conversation has passages, they are sent to the model instead of the active document and the live selection, with a note that the full document is not included (documents pinned by hand still go); the model can still read it with `read_file` or change a passage with `replace_text`. The input box gets the focus: nothing is sent until the user writes.
- User attachments (paperclip, paste, drag and drop; up to 10 per message): only formats the active model reads natively, images when it has vision and PDF files when it has the `pdf` capability (see [chatAttachments.js](../../lib/chatAttachments.js.md)); the attach button explains what the chosen model cannot read. They are saved in `.ow/chat/attachments/`; only the most recent ones are re-sent to the model (8 user images and 4 PDFs from the user side, 4 images returned by tools), the others stay as a text note.
- Token usage: each assistant reply shows its input/output tokens (summing every request of the step), and the header shows the conversation total.
- Writing skills: chips for the skills active in the conversation (project defaults plus the ones added here, marked differently; × removes one), a selector to add more, the skills' quick actions next to the built-in ones, and "Create a writing skill" from the conversation, the selection, the open document or a pasted text, through the generation and editing dialogs of [SkillsManager.jsx](SkillsManager.jsx.md). The active skills are re-read at every step and injected into the system prompt after the project instructions.
- The system prompt states the reply language and the language of the documents (which can differ), that whatever the user will copy and paste outside the document (commands, code, configuration, prompts, a message to send) goes in a fenced code block with its language, never fenced otherwise and never nested, the `<next_prompt>` convention, the project instructions of every enclosing `.ow` (the nearest prevailing), the skills, the project memory and the previous conversations used as context; embedded base64 images are abbreviated before being sent.
- Streaming responses with text, reasoning and status events; requests can be cancelled, a tool call in preparation is announced, and a run can be resumed from a chosen point.
- Tool loop: parses the fenced `<tool_call>…` blocks emitted by CLI providers, executes the requested tool through the bridge (project reading, file creation, moves and deletes, notes and bookmarks, editor edits, web browsing, screenshots and saved image descriptions, questions), sends back tool results, and enforces the configured maximum of chained tool steps (with the optional automatic continuation). Questions with choices are shown as a card in the conversation: one option per row with its number (keys 1–9 pick it, but not while typing in a field or in the document), a multiple-choice question confirms with the count of the picked ones, an `ordered` one asks for the order (a badge with the position, "Choose in the order you prefer: the sequence matters"), and long lists are paged ("Page 1 of 2 · 12 choices"). "Other…" opens a free field ("Type your answer…", Enter sends) and "Skip" answers nothing. When the tool fixes a default choice with a few seconds, its row shows a countdown ring and the answer goes on its own unless the user touches the card. A sequence of questions (`AskCard`) is walked one at a time with "Question 2 of 3", dots for what is already answered, "Back" to change an answer and "Cancel" to drop the whole questionnaire; the answers go back to the assistant together, and the card takes the focus at every question so keys and Tab work at once.
- Research assistant: when it is enabled and a model is chosen in the settings, the `research` tool becomes available (only with a project folder, and never in the no-project mode), and the panel runs it through `runResearch` ([researchAgent.js](../../lib/researchAgent.js.md)) — a separate loop with a second model and only reading tools, whose status ("Researching… (step N)") replaces the live status of the reply and whose report comes back as the tool result. Its requests are registered so that cancelling the run stops them too.
- Requests coming from outside the chat: a prompt handed over by an external agent through the MCP server's `ask_agent` arrives as a normal user request labelled with the agent's name (the attachment carries `source: 'mcp'` and the agent, so it is clear it was not written by the user), in a new conversation (`newChat`) or in the one open; it starts as soon as the model is free, and the caller is told in which chat and at which message index the request landed.
- Renders notes with accept/reject controls and applies editor edits through the editor with undo support; an image returned by a tool or attached by the user can be opened in the full-screen viewer ([ImageViewer.jsx](ImageViewer.jsx.md)).

The model is chosen in the composer with [ModelPicker.jsx](ModelPicker.jsx.md) (search by name, filter by accepted input). The other options sit beside it in the three-dot menu of [ChatOptionsMenu.jsx](ChatOptionsMenu.jsx.md): the reasoning effort of the provider, the temperature of the conversation as a level from 0 to 1 ([temperature.js](../../lib/temperature.js.md), shown with the band name and inheriting the level of the project or of the provider when it is not set), and, with a project open, whether the edits of the assistant are to be reviewed or approved and saved automatically ("Approve for me" also closes the documents the assistant opened; the previous version stays in the history). The approval choice of the chat is per project: it starts from the project's `ai.autoApprove`, falls back on the general preference `openwriter.autoApprove`, and the third option "As in the general settings" (which says whether the general setting is approving or reviewing) clears the project's own choice, saved at once with `setProjectAiOptions` ([project-file.cjs](../../../electron/project-file.cjs.md)). 

All the options are disabled while a turn is running, and at the end of a turn `autoApproveRef` accepts the pending edits of the documents the assistant touched.

**Messages sent during a turn.** A message written while the assistant is working is not lost: it waits in the queue shown above the composer as "Queued" (with the tooltip "Queued task: it starts when the assistant has finished the current work"), or as "Now" when it was sent with Ctrl/Cmd+Enter (tooltip "Sent with Ctrl+Enter: it reaches the assistant as soon as the tool in progress has finished"). A queued item can be taken back (`unqueue`), and the queue is saved at once with `setQueue` of the chat store, so it survives an abrupt stop. When the step is free, the waiting messages are sent together as one user message marked `queued`: the assistant is told that the user wrote it while it was working, and the message carries no document context of its own (that stays on the real request). The Stop button of the composer interrupts the turn.

The chat accepts SVG attachments: since models read pixels, an SVG is rasterised to a PNG before it is sent ([svgRaster.js](../../lib/svgRaster.js.md)). An image of the conversation can be opened full screen in [ImageViewer.jsx](ImageViewer.jsx.md), where the wheel zooms, dragging moves and a double click toggles between fit and real size; a thumbnail and the viewer carry the two buttons of `ImageActions` (copy the image, save it), which show a check for a moment or the error.

The web pages the user added to the context ([web-references.cjs](../../../electron/web-references.cjs.md)) are listed in the system prompt (title, address and `@web/…` path, up to 30) next to the project memory; the assistant reads one with `read_file` and finds passages in them with `search_knowledge`.

**Resuming an interrupted turn.** "Resume from here" appears whenever the turn is incomplete, not only after an error or a bare user message: also after a stop (the interrupted reply is saved with `interrupted: true`), after a tool call that never got a result, and after a result the model did not answer ([chatResume.js](../../lib/chatResume.js.md)). The resumed run starts from the last saved step, so the work already done is not repeated.
