# AiChatPanel.jsx

Source: [`src/components/AiChatPanel.jsx`](../../../../../src/components/AiChatPanel.jsx)

Assistant side panel. Largest UI component of the app.

- Conversation threads: list with the parent branch marked, create, rename, delete, open the `.ow/chat` folder, and branching (`parentId`, `branchedAt`, and `contextFrom` links to previous conversations used as context, added or removed as chips). Editing a previous message removes the replies after it.
- Message composer with the context documents (the active one included automatically, the others pinned or not), image and PDF attachments, and the quick actions (the project's own first, then the general ones — by default proofread, rewrite, summarize, lengthen, review — see [quickActions.js](../../lib/quickActions.js.md)) followed by the actions of the active skills.
- Passages under discussion: a passage selected in the document (from [SelectionToolbar.jsx](SelectionToolbar.jsx.md)) is attached to a new or the current conversation as a chip (× removes it) and saved with it (`passages`). While a conversation has passages, they are sent to the model instead of the active document and the live selection, with a note that the full document is not included (documents pinned by hand still go); the model can still read it with `read_file` or change a passage with `replace_text`. The input box gets the focus: nothing is sent until the user writes.
- User attachments (paperclip, paste, drag and drop; up to 10 per message): only formats the active model reads natively, images when it has vision and PDF files when it has the `pdf` capability (see [chatAttachments.js](../../lib/chatAttachments.js.md)); the attach button explains what the chosen model cannot read. They are saved in `.ow/chat/attachments/`; only the most recent ones are re-sent to the model (8 user images and 4 PDFs from the user side, 4 images returned by tools), the others stay as a text note.
- Token usage: each assistant reply shows its input/output tokens (summing every request of the step), and the header shows the conversation total.
- Writing skills: chips for the skills active in the conversation (project defaults plus the ones added here, marked differently; × removes one), a selector to add more, the skills' quick actions next to the built-in ones, and "Create a writing skill" from the conversation, the selection, the open document or a pasted text, through the generation and editing dialogs of [SkillsManager.jsx](SkillsManager.jsx.md). The active skills are re-read at every step and injected into the system prompt after the project instructions.
- The system prompt states the reply language and the language of the documents (which can differ), the `<next_prompt>` convention, the project instructions of every enclosing `.ow` (the nearest prevailing), the skills, the project memory and the previous conversations used as context; embedded base64 images are abbreviated before being sent.
- Streaming responses with text, reasoning and status events; requests can be cancelled, a tool call in preparation is announced, and a run can be resumed from a chosen point.
- Tool loop: parses the fenced `<tool_call>…` blocks emitted by CLI providers, executes the requested tool through the bridge (project reading, file creation, moves and deletes, notes and bookmarks, editor edits, web browsing, screenshots and saved image descriptions, questions), sends back tool results, and enforces the configured maximum of chained tool steps (with the optional automatic continuation). Questions with choices are shown as a card in the conversation.
- Research assistant: when it is enabled and a model is chosen in the settings, the `research` tool becomes available (only with a project folder, and never in the no-project mode), and the panel runs it through `runResearch` ([researchAgent.js](../../lib/researchAgent.js.md)) — a separate loop with a second model and only reading tools, whose status ("Researching… (step N)") replaces the live status of the reply and whose report comes back as the tool result. Its requests are registered so that cancelling the run stops them too.
- Requests coming from outside the chat: a prompt handed over by an external agent through the MCP server's `ask_agent` arrives as a normal user request labelled with the agent's name (the attachment carries `source: 'mcp'` and the agent, so it is clear it was not written by the user), in a new conversation (`newChat`) or in the one open; it starts as soon as the model is free, and the caller is told in which chat and at which message index the request landed.
- Renders notes with accept/reject controls and applies editor edits through the editor with undo support; an image returned by a tool or attached by the user can be opened in a full viewer.

The model and the reasoning effort are chosen in the composer with [ModelPicker.jsx](ModelPicker.jsx.md) (search by name, filter by accepted input) and the efforts of the provider.
