# aiTools.js

Source: [`src/lib/aiTools.js`](../../../src/lib/aiTools.js)

Renderer-side tool layer of the assistant: defines the tool catalog (`TOOL_DEFINITIONS`, grouped by `files`, `create`, `notes`, `memory`, `edit`, `web`, `vision`, `ask`), builds the tool prompts and function-calling schemas, parses tool calls, and executes them through `createToolRunner`.

Tools implemented here:

- Read: `list_directory` (name or date order, and `@name/…` for a reference folder), `read_file` (open documents are read from the live editor, including unsaved changes; disk files through the project tools), `list_versions`, `read_version`.
- Create: `create_directory`, `create_file` (never overwrites; optional same-name allowance and `open` in a tab), `create_project` (only with no project open: creates the folder where the user chooses and links the open documents instead of copying them), `move_file`, `delete_file` (trash, with user confirmation dialog).
- Notes: `add_note` (single or batched up to 20; suggestions anchored to exact quotes through the anchoring helpers), `set_ai_score` (the AI-likelihood result shown in the document toolbar), `list_notes` (status filter, all-project option), `update_note` (assistant-authored notes only; re-anchoring after text edits; a `resolution` explains a closure; only open/resolved status changes — accepting and rejecting stay with the user).
- Bookmarks: `list_bookmarks` (also only the flagged ones), `add_bookmark` (a named anchor to link as `file.md#name`, with label, note and flag), `update_bookmark` (name, label, note, flag, re-anchoring), `remove_bookmark`.
- Memory: `remember`, `update_memory` and `forget` (assistant-authored entries only), `recall`.
- Edit: `open_document`, `replace_document` (full rewrite), `replace_text` (unique find, tolerates Markdown-escaped input), `insert_text` (after/before/start/end with anchor); they all take an optional `path` for a document other than the active one. Every edit first snapshots the document into history ("Before the AI edit"), passes through [pendingChangesExtension.js](pendingChangesExtension.js.md) so it stays reviewable, and results mention undo via Ctrl+Z. This is also the set the MCP bridge runs on the live editor ([mcpRequests.js](mcpRequests.js.md)).
- Web: `browser_tabs`, `browser_read`, `web_open` (http(s) only, private and local hosts blocked), `web_search` (DuckDuckGo HTML), `browser_navigate` (back/forward/reload), `browser_follow_link` (by number, text, or address), `browser_history` (the pages the assistant itself opened, never the user's, through its separate history), `web_read` (chunked page text; links and image lists cached per tab).
- Vision: `screenshot_document`, `screenshot_browser`, `describe_image` (saves a description of a project image, which `view_image` then returns instead of the image, so the same image is never looked at twice) and `view_image` (project file, URL, or page image number; `again` forces the image itself).
- Ask: `ask_choice` (single, `multiple`, or `ordered` choices; 2–60 options; page size 2–10; "Other" toggle; up to 8 sequential questions; tolerates options passed as strings).

With no project folder (`enabled.loose`) only the tools that work on the documents open in tabs are available: `NEEDS_FOLDER` (`list_directory`, `create_directory`, `create_file`, `move_file`, `delete_file`, `open_document`, `describe_image`) is filtered out, while `create_project` exists only in that mode (`ONLY_LOOSE`), since it is how the assistant gets a project.

Protocol utilities: `toolSchemas(enabled)` builds Ollama-style function-calling schemas filtered by the enabled groups, and `toolAvailable(tool, enabled)` tells whether a single tool is available in the current mode. `toolsPrompt(enabled, options)` renders the plain-text protocol used by the CLI providers (the model answers by writing its call block as text), with per-group usage hints, untrusted-content rules, and the active document path; the `native` variant omits the block syntax when the provider already supports function calling; chaining is capped by `maxSteps` (default `DEFAULT_MAX_TOOL_STEPS` = 30, adjustable in Settings). `parseToolCall(reply)` extracts and validates the call with lenient JSON parsing (raw newlines inside strings, stray trailing characters) and a bare-JSON fallback. `visibleText(reply)` hides the call block while streaming, and `splitNextPrompt(reply)` separates the trailing suggestion line. `describeCall(name, args)` produces the short user-facing description of a running tool, and `relativeToProject` converts absolute paths to project-relative ones. The tools the user turned off are named in the prompt (`disabledNotice`), with the label of the option, so the model asks for them to be turned on instead of working around them.
