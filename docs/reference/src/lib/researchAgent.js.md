# researchAgent.js

Source: [`src/lib/researchAgent.js`](../../../../src/lib/researchAgent.js)

The research assistant: a second model, configured separately (Settings → AI → Research assistant), that the main assistant calls as the `research` tool ([aiTools.js](aiTools.js.md)). It explores the project on its own and returns a short report with file paths and line numbers, so that the many readings of an exploration stay out of the main conversation. It never writes anything, and nothing of it appears in the chat except the status line ("Researching… (step N)") and the report, which comes back as the result of the tool call.

- `READ_ONLY_TOOLS`: the only tools it can run — `search_files`, `list_directory`, `read_file`, `list_versions`, `read_version`. Any other call is refused with a message naming the ones it may use.
- `SYSTEM_PROMPT`: the instructions of the second model — start from `output=files`, judge with `output=lines` and a little context, pass `glob` to search source code (by default only `.md`, `.markdown` and `.txt` are searched), read the lines needed with `startLine`/`endLine`, number every item of a list and give the total, search every place where something could live before saying it is not there, cite paths and line numbers exactly, mark uncertain findings "(not verified)"; the answer is a concise report (about 400 words) of findings "path:lines — what it says", then an optional line `Not found:` and a final line `Searched: …`.
- `runResearch({ question, scope, settings, api, chat, project, toolBridge, onStatus, register, isCancelled })`: runs the loop. `settings.researcher` gives `provider`, `model` and `maxSteps`; `scope` (optional) restricts the exploration to what the caller names; `chat` is the streaming API of the renderer (`electronAPI.ai`), and every request uses `reasoningCap: 'low'`; `register(cancel)` hands the interface a way to stop the request and `isCancelled()` reports an interruption. The project tools are the same as the assistant's, with only `files` enabled, so unsaved editor text also counts ([aiTools.js](aiTools.js.md)).
- The loop: up to `maxSteps` calls; at the last step the model is told to write the report without calling a tool; an empty reply is retried twice with an explicit invitation and then the report is requested once more (an empty answer is seen with some models after the reasoning); a malformed call is sent back as an error message and the model corrects it.
- `prune(messages)`: earlier tool results are cut to their first 500 characters (`OLD_RESULT_CHARS`), keeping the last `KEEP_FULL_RESULTS` (6) results whole, so the context of the researcher stays small.
- Limits: at most 8,000 characters of report (`MAX_REPORT_CHARS`) and 12,000 per tool result (`MAX_RESULT_CHARS`).
- The result is a string: the report (cut at `MAX_REPORT_CHARS`), then a footer between brackets with the model, the number of steps, the first eight of them (name and the searched pattern or path) and the tokens used (`↑` input, `↓` output), plus a warning that the assistant only reads, so paths and lines are reliable but interpretations may not be — the few points that matter are to be verified with `read_file` and `startLine`/`endLine`.
- `brief(name, args)`: the short form of a call used for the status line and for `steps`.

Without a project folder the tool is not available (`NEEDS_FOLDER` in [aiTools.js](aiTools.js.md)), and the main assistant is told to turn it on in the settings when it asks for it with the group off.
