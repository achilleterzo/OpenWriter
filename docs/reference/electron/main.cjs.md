# electron/main.cjs

Source: [`electron/main.cjs`](../../../electron/main.cjs)

Main process entry point. Creates the application window, registers every IPC handler, and owns the global state shared by the backend stores: the current project path, the provider layer, the project file, the chat, notes, bookmarks, memory, links and references stores, the skills store, the fonts and browser history stores, and the project tools.

Document reading is centralized in this module. Markdown files are returned as-is; DOCX files are converted through mammoth; PDF text and images come from [pdf-import.cjs](pdf-import.cjs.md), with each image put back where it was on the page and embedded as `data:` until the save puts it in `images/`. Sessions are stored per project in the Electron user data directory, including open tabs, unsaved drafts, the pending assistant edits, and the side panel state.

The `ow-file://` scheme is registered as privileged and serves the document images read-only. When no project is open, the built-in main project (`main/` in the application data) takes its place for conversations, notes, memory, context and skills, and always keeps the history and notes of documents opened from outside the project.

Other responsibilities:

- File dialogs for opening and saving documents, with supported-extension filters, and documents handed over by the operating system (`.md`, `.markdown`, `.mdown`), kept for the renderer if it is not ready yet.
- Workspace operations limited to the project directory: rename, delete with a confirmation dialog and trash (a Markdown document goes to the trash together with its DOCX/PDF original, which is named in the confirmation; the answer lists every path deleted so that the open tabs close) (`workspace:delete-paths` deletes several items with one confirmation that counts them and lists the first names; an item inside another deleted folder is not counted twice), reveal in the file manager, unique-destination import with drag and drop, creating an entry, moving an item into a folder, and directory listing that hides dot folders, `node_modules`, `dist`, and `out`. Files can be copied or cut to the system clipboard and pasted back ([file-clipboard.cjs](file-clipboard.cjs.md)).
- Moving a document carries its images along ([document-images.cjs](document-images.cjs.md)) and moves history, notes, bookmarks and memory entries with it.
- Export to PDF through a hidden print window, to DOCX through html-to-docx, and to a self-contained Markdown with the images embedded ([markdown-embed.cjs](markdown-embed.cjs.md)).
- Project extras: icons ([project-icon.cjs](project-icon.cjs.md)), linked documents, reference folders, the shareable setup file ([project-pack.cjs](project-pack.cjs.md)), sub-projects moved in and out, and moving a whole project.
- Bookmarks, memory and the browser history (the user's and the assistant's, kept apart) through their stores.
- Images: downloads, normalization and screenshots through [images.cjs](images.cjs.md), imported images placed in the `images/` folder next to the document, screenshots of a browser tab saved in the project's `screenshots` folder, and the descriptions the assistant saves of project images (`images:read-description` / `images:write-description`: one Markdown file per image in `.ow/image-descriptions/`, named after the project path of the image and holding at most 20,000 characters; the assistant writes them with `describe_image` and gets them back instead of the image, unless it asks for the image again). The directory listing for the assistant flags those images with `described`, so it knows it can read the description instead of looking at the file ([aiTools.js](../src/lib/aiTools.js.md)).
- Spell-check configuration, with project settings overriding global languages, and edit context-menu events sent to the renderer; confirmations asked by the main process go to the renderer's internal dialog (`dialog:ask` / `dialog:answer`).
- Chat attachments chosen by the user (`chat:pick-attachments`, `chat:read-attachment`, `chat:prepare-image`): only images (up to 8 MB, normalized; formats Electron cannot decode come back as `raw-image` for the renderer to convert) and PDF files (up to 20 MB, `%PDF-` header checked), also from outside the project.
- Writing skills through the `skills:*` channels; `skills:import-file` picks a Markdown file and returns its parsed fields through `skillFromMarkdown` without saving.
- Project settings extras: `project:set-quick-actions` saves the quick actions of the project alone ([project-file.cjs](project-file.cjs.md)) and `project:context-chain` returns the `.ow` chain enclosing a document. The text search of the assistant is `tools:search-files`: the project tools search ([project-search.cjs](project-search.cjs.md)) run inside the project or inside a reference folder when the path starts with `@name/`, with the results formatted for the model by `formatSearch` and the reference prefix put back on each path. The endless or paged view chosen in the menu reaches the renderer as `view:changed`.
- UI preferences in the application data (`preferences:load`, read synchronously at startup, and `preferences:set`), with `localStorage` as a fallback on the renderer side.
- Fonts: the Google Fonts catalog, the list of installed fonts, install and remove ([fonts.cjs](fonts.cjs.md)).
- The MCP server: `mcp:get-config` returns the command and arguments an agent's client has to use ([mcp-server.cjs](mcp-server.cjs.md)). The HTTP transport ([mcp-http.cjs](mcp-http.cjs.md)) is a child process started only when the preference `openwriter.mcpHttp` is on (and at startup if it was left on): `mcp:http-status` and `mcp:http-set` read its state, turn it on and off and renew its token, and the read-only preference `openwriter.mcpHttpReadOnly` is passed to each start. The main process also runs the local bridge ([mcp-bridge.cjs](mcp-bridge.cjs.md)) that forwards the agent's requests to the interface (`mcp:request` / `mcp:response`) — the editor edits, opening a document or a project in the app, and a task handed to the assistant — gated by the preference `openwriter.mcpEdit`. Paths are compared through [path-compare.cjs](path-compare.cjs.md), and confirmations (delete, move) are asked in the interface (`dialog:ask` / `dialog:answer`).
- Window state persistence, restored only when still visible on a connected display.
- The BrowserWindow hosting the renderer loads the Vite dev server in development and the built bundle in production.


**Search index** (see [knowledge-service.cjs](knowledge-service.cjs.md)): `project:knowledge-status` / `project:knowledge-rebuild` (also for a project that is not open), `tools:search-knowledge`; saving the project settings applies `options.searchIndex` (`applyKnowledgeChoice`: off clears the project's entries, on starts a scan). `knowledgeOn` caches the choice for the open project so that the watcher does not read the settings at every event.

**Search by meaning**: `semanticPacks.cpu` and `semanticPacks.gpu` (see [semantic-pack.cjs](semantic-pack.cjs.md)) live in `userData/semantic`, and `gpuContext` ([gpu-context.cjs](gpu-context.cjs.md)) is the hidden WebGPU window. The device is chosen in Settings → Local models (preference `openwriter.localModels.device`, `cpu` by default): `activeDevice()` is the GPU if it is chosen, its pack is installed and it has not failed in this session (`gpuFailure`), otherwise the CPU if its pack is installed, otherwise none. The search by meaning **does not depend on the open project or on a per-project option**: `semanticAvailable()` (a model is installed and enabled in Settings → Local models, so every search can be by words and by meaning) decides whether searches use the vectors, and `semanticTargets()` — the passages to vectorize — is the open project, its reference folders and the other shared projects, all those whose index is on. A project that does not want to be in it turns its index off. `configureSemantic({ purge })` tells the worker the device, the model id and the projects (called when a project starts, when settings are saved, when a pack is installed or removed, when the device changes, and when the GPU fails); `tools:search-knowledge` passes `semantic: true` only when there are targets. When the worker reports a GPU failure (`onSemanticError`), `gpuFailure` is set and the CPU takes over; choosing the card again clears it. IPC: `semantic:status` (both packs, wanted and active device, graphics card info and last failure, vectors progress of the open project), `semantic:install` / `semantic:remove` (take the device; removing a pack also drops that model's vectors and releases the GPU window), `semantic:set-device`, `semantic:set-enabled`, `semantic:probe-gpu` (asks WebGPU which adapter it would use, without loading the model). Nothing is downloaded unless the user asks for it.


**Shared knowledge**: `sharedFolders()` / `outsideFolders()` (see [shared-knowledge.cjs](shared-knowledge.cjs.md)) add the user's other projects to the reference folders for search (`tools:search-knowledge`, `scope` `all` / `project` / `others`), for reading (`@name/…`, `outsideRoot`), for the root listing and for the vectors; `startKnowledge` scans them at project opening (throttled to every two minutes each). The global switch of the model is the preference `openwriter.localModels.embeddings` (`semantic:set-enabled`, off means `semanticTargets()` is empty for every project); `knowledge:activity` returns `{ scanning, vectors }` for the progress bar. Saving the settings of another project calls `configureSemantic()` because its sharing choice changes what is searched. The search is the function `searchKnowledgeTool(args, readTool)`, used by the IPC `tools:search-knowledge` and, as a local tool of the MCP bridge, by external agents (with `read_document` as the tool named in the answer).

**Search from any project**: the search is `searchKnowledgeTool(args, readTool, { project })`. The open project is not required: an external agent (through the MCP bridge) says which project it works in, and the app searches from there (that project, its reference folders and the other shared projects); with no project at all (the agent works in no project and the app has none open) it searches every shared project. A project that is not in the list of known projects is treated as no project. `outsideFor(base)` gives what is outside a project.

**Web references**: `webStore` (see [web-references.cjs](web-references.cjs.md)); `referenceFolders()` adds `.ow/web` as the automatic reference folder `@web` (indexed, watched, vectorized and read like the others), `outsideFolders()` also the pages of the shared projects (`@<project>-web`); IPC `webrefs:list`, `webrefs:find`, `webrefs:save`, `webrefs:remove` (`webReferencesChanged` re-aligns the index at once).
