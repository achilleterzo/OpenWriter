# electron/ai-providers.cjs

Source: [`electron/ai-providers.cjs`](../../../electron/ai-providers.cjs)

AI provider layer for six backends: Ollama, Ollama Cloud, OpenRouter, Codex CLI, Claude CLI, and Gemini.

- Ollama and Ollama Cloud share one driver (`PROVIDER_META`: `driver: 'ollama'`, default endpoint, `keyRequired`) and talk to the native HTTP API with NDJSON streaming. The `endpoint` is configurable for both (defaults `http://localhost:11434` and `https://ollama.com`, trailing slashes removed); `ollamaTarget` resolves it and `ollamaOptions` adds the `Authorization: Bearer` header only when a token exists. The token is optional for Ollama (`ollama-key.bin`) and required for Ollama Cloud. `keepAlive` applies to local Ollama only; `numCtx` to both.
- Keys are encrypted through `safeStorage` and stored in the Electron user data directory, one file per provider (`<provider>-key.bin`); `keyProvider` rejects unknown provider names. `usableProvider` checks `keyRequired`, not whether the provider merely accepts a key. `createAiProviders`, `claudeIsolationArgs`, `normalizeProviderConfig` and `PROVIDER_META` are exported.
- OpenRouter uses its own encrypted key (`openrouter-key.bin`) and the OpenAI-compatible `/api/v1/chat/completions` endpoint with SSE streaming; native tool calls, images, PDF files (`type: 'file'` parts, with the `file-parser` plugin set to the `native` PDF engine) and reasoning effort are translated from the Ollama-style messages the renderer sends; requests ask for `usage: { include: true }`.
- Gemini uses a Google AI Studio API key, encrypted the same way (`gemini-key.bin`), on the OpenAI-compatible `/v1beta/openai` endpoint; its model list keeps only the models that generate text (embeddings, image, audio and the like are filtered out).
- OpenRouter and Gemini are no longer special cases in the code: the request is composed from their descriptor ([provider-descriptors.cjs](provider-descriptors.cjs.md)) and the answer is read by the shared codec ([openai-chat.cjs](openai-chat.cjs.md)); a 400 on a request that carried a reasoning parameter is repeated without it for every service. Model lists, public catalogs and fixed capabilities come from the same descriptors.
- The compatible servers: `openai` is the first, and the user can add more (ids `openai-<code>`, up to 20 in all, saved in `providers` like the others and kept by `normalizeSettings`; an id that does not match the pattern is dropped, and a chosen provider that no longer exists falls back to Ollama). Everything below holds for each of them, and a key is stored per server (`<id>-<preset>-<hash of the address origin>`). A conversation, project choice or research model that points to a server that was deleted is ignored and the active provider is used. `labelFor(provider)` gives the name shown. The first server, `openai`, reaches any server that speaks that protocol through a preset (LM Studio, llama.cpp, vLLM, OpenAI, Groq, Together, Mistral, DeepSeek, or a custom address). Its settings hold `preset`, `endpoint` (the preset's address when empty or invalid), the usual `model`, `reasoning`, `temperature` and `numPredict`, a `name` (up to 40 characters; `label` is the name shown: the user's, or the service's when empty) and two settings, `vision` and `tools`, each `'auto'` (default), `'on'` or `'off'` (older yes/no values convert: `true` becomes `'on'`, `false` for tools `'off'`). `getCapabilities` answers from them: `'on'` and `'off'` win; in `'auto'` the server is asked when it is Ollama behind `/v1` (`detectOllamaCapabilities`: `GET <root>/api/version` recognises it, `POST <root>/api/show` lists `capabilities`, with a 5 s timeout and the token if there is one; the result is remembered for 5 minutes, a failure for 1), otherwise images are off and tools on. The answer carries `detected`, true when the server said it. The token is optional for local presets and `custom`, required for hosted ones (`keyIsRequired`, which `usableProvider` and the status use). The key is stored per preset and per server: its file is `openai-<preset>-<hash of the address origin>-key.bin`, so changing the address or the preset never sends it to another host. `descriptorFor(provider, endpoint)` gives the descriptor of any OpenAI-compatible provider; `listModels` accepts the address typed in the settings before it is saved. PDFs are not offered to it.
- The settings also keep `activeProviders` (the providers shown in the settings: those the user added, always including the chosen one; settings saved before it existed show the providers that already have a model) and `providerIcons` (custom icons as PNG, JPEG or WebP data URLs of at most 80,000 characters, for the custom provider (`openai`) only, since the others keep their logo; SVG is refused). Removing a provider from the list does not delete its configuration or key.
- Codex and Claude are spawned as CLI child processes, resolved on Windows through `where.exe` and known install roots, invoked through PowerShell quoting, and terminated as a process tree on cancel.
- CLI settings are normalized per provider, including reasoning-effort levels, and the `*_API_KEY` environment variables are removed from child processes so that an ambient key cannot silently switch the authentication mode.
- The prompt sent to a CLI instructs the model that it is not a coding agent and that OpenWriter tools must be requested by writing a fenced `<tool_call>…` block as plain text; the app parses that block and executes the requested tool, enabling multi-step tool chains up to the configured limit.
- `chatStream` messages may carry `files: [{ mime: 'application/pdf', name, data }]`. Only OpenRouter and Claude accept them: Claude receives them as `document` blocks of a stream-json message, with `[Document N: name]` placeholders in the prompt; the other providers throw. `getCapabilities` returns `{ known, vision, tools, pdf }` (`pdf`: Claude always, OpenRouter when the model accepts `file` input). `listModelInputs({ provider, endpoint })` returns `{ [id]: { vision, pdf } }` for every model of a provider (OpenRouter from the catalog, Ollama through one cached `/api/show` per model, six at a time), leaving out the models whose capabilities are unknown; it feeds the input filter of the model picker.
- Besides `text`, `thinking` and `status`, the stream emits `{ type: 'usage', input, output }` token counts: from Ollama's final `done` line, OpenRouter's `chunk.usage`, the Claude CLI `result` event (input includes cache creation and cache read tokens), and Codex's `turn.completed`.
- `normalizeSettings` also covers what is not provider-specific: the assistant language, the quick actions (`null` = all defaults; default ids are never lost, at most 12 user actions), auto-continue after the tool-chain limit and its countdown, `maxToolSteps` (1–50, default 30), and the tool groups (`files`, `create`, `memory`, `notes`, `vision`, `ask`, `edit`, and `web`, which is opt-in).
- `researcher` (through `normalizeResearcher`): the second model of the research assistant — `enabled` (off unless explicitly turned on), `provider` restricted to the providers with native tool calls (`RESEARCH_PROVIDERS`: Ollama, Ollama Cloud, OpenRouter, Gemini, `ollama-cloud` by default), `model` (empty until chosen) and `maxSteps` (2–30, default 12). It is the model the `research` tool calls ([researchAgent.js](../../src/lib/researchAgent.js.md)).
- `toolReasoning`: the reasoning effort of the steps that follow a tool result — `same` (as configured), `reduced` (at most "low", the default) or `none` (turned off where the provider allows it).
- Settings are persisted in `ai-settings.json`, and diagnostic lines are appended to `ai-diagnostics.log`, truncated at 1 MB.
- **Isolated CLIs.** Codex starts with `--ignore-user-config` and without shell, apps, browser or computer use. Claude starts with `--tools ''`, `--strict-mcp-config` with an empty MCP config file in the application data (`claude-empty-mcp.json`, a file and not a JSON string because PowerShell eats the quotes) and `--disable-slash-commands` (`claudeIsolationArgs`), so it sees no MCP server, skill or command of the user: the tools of the app reach both only as text in the prompt.
- **Effective settings.** `getEffectiveSettings()` is `getSettings()` with the model chosen by the open project on top (`getProjectModel`, given to `createAiProviders`; see [model-choice.cjs](model-choice.cjs.md)); `activeProvider` and `providerConfig` read it, so every request follows the project. `getSettings()` stays the raw general settings, which the settings page reads and writes. `chatStream` also takes a `selection` (`{ provider, model, reasoning }` of the conversation), which prevails over both; `getCapabilities(model, provider)` can be asked about that model.
- **Temperature.** Each request carries the level of the conversation (0–1); `levelFor(conversation)` picks the conversation level and, when it is empty, the level of the open project (`getProjectTemperature`, given to `createAiProviders`), and `temperatureFor(provider, conversation)` converts it into the degrees of the provider with `nativeTemperature` ([temperature.cjs](temperature.cjs.md)) or, when there is no level, falls back to the general `temperature` of the provider (0–2, empty meaning the model default). The value reaches Ollama as `options.temperature`, OpenRouter and Gemini as `temperature`. The CLIs have no such parameter: the extreme bands (below 0.2 and from 0.8) become a style instruction appended to the prompt with `styleHint`, about precision or about freedom of prose, never about facts or the format of tool calls.
