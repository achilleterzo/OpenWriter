# electron/project-search.cjs

Source: [`electron/project-search.cjs`](../../../electron/project-search.cjs)

Text search in the files of a project, literal or with a regular expression — the same search for the internal assistant (through `tools:search-files` in [main.cjs](main.cjs.md)) and for the MCP server ([mcp-server.cjs](mcp-server.cjs.md), [project-tools.cjs](project-tools.cjs.md)). It replaces the `search` that [project-tools.cjs](project-tools.cjs.md) used to hold, which now only delegates to it.

- `searchFiles(options)`: returns a promise of a result object. Options: `root` (absolute project folder) and `start` (the folder to search in), `pattern` (required), `regex` (literal when false), `caseSensitive`, `glob`, `output` (`files`, `lines` or `count`), `context` (lines around each match), `maxResults` and `overrides`.
- `output=files` (the default) lists the files that contain the pattern with their number of matches — the cheapest answer, so that only the files that matter are read; `lines` gives the matching lines with `context` lines before and after; `count` only the totals.
- Without `regex`, a pattern that contains regular-expression symbols (`|` for alternatives, `\s`/`\w`/`\d`, `.*`, `.+`, `[^…]`, `(?:…`) is read as a regular expression and the result says so (`autoRegex`); `regex: false` forces the literal text.
- Only `.md`, `.markdown`, `.mdown` and `.txt` are searched unless `glob` is given (`"*.js, *.jsx, *.cjs"`, `"src/**/*.js"`, `"*.md, *.js"`): a glob with a `/` is matched against the project-relative path, otherwise against the file name; several globs are comma separated.
- `overrides`: `[{ path, text }]` with the unsaved text of the documents open in the editor, which is searched instead of the older file on disk; the result counts them (`unsavedEditsIncluded`).
- Limits: files up to 2 MB and without NUL bytes, up to 20,000 files visited, `maxResults` 50 by default and 500 at most, `context` 5 lines at most, long lines clipped at 240 characters around the match, about 30,000 characters of output. A result that hits a limit comes back with `truncated` and a note saying how to narrow it.
- `.ow`, `.git`, `node_modules` and any name starting with a dot are skipped; folders and files are visited in name order.
- Regular expressions run in a worker thread with a 10-second deadline (`REGEX_TIMEOUT_MS`), so a pathological expression cannot freeze the application: the worker is terminated and the promise rejects with a message asking to simplify it. Patterns are capped at 2,000 characters (`MAX_PATTERN_CHARS`, enough for an alternation of dozens of names), and an expression with a quantified group inside a quantified group (`(a+)+`) is guarded; literal searches run in the main thread, since they cannot be catastrophic. Without worker support the search runs guarded in the main thread.
- When a literal pattern has no matches and contains regular-expression symbols, the result carries a `hint` suggesting `regex=true`.
- The result holds `pattern`, `regex`, `output`, `filesSearched`, `filesMatched`, `totalMatches`, `shown`, `results`, and optionally `unsavedEditsIncluded`, `hint`, `autoRegex` and `truncated`.
- `formatSearch(result)`: the text an AI model reads — a header ("N matches in M files (K files searched[, U with unsaved edits from the editor]) for text “pattern”", with the note when the pattern was read as an expression), then one line per file (`path (N)`) or one per match (`path:line: text`, with the context lines indented as `path-  text`), and the truncation note at the end.
