# electron/mcp-server.cjs

Source: [`electron/mcp-server.cjs`](../../electron/mcp-server.cjs)

OpenWriter as an MCP server on stdio: it gives external agents (Claude Code, Codex, OpenCode, clients built into IDEs) what the files alone do not show — the project context and instructions, skills, notes, bookmarks and memory — together with listing, reading and searching the documents.

It never writes to the document files. It can add notes, suggested replacements and bookmarks (stored in `.ow`, reviewed in OpenWriter), and, with the application running, change the documents open in the editor through the bridge ([mcp-bridge.cjs](mcp-bridge.cjs.md)): those edits are marked for the user to accept or reject, can be undone, and reach the file only when the user saves. With `--read-only` every writing tool is absent. The notes, suggestions and bookmarks do not depend on Electron, so they work with the application closed; the editor edits and `read_open_document` need it running.

It is a standalone script: JSON-RPC 2.0, one message per line on stdin/stdout, diagnostics on stderr. The protocol versions it accepts are listed in `SUPPORTED_PROTOCOLS`, answering `initialize`, `ping`, `tools/list` and `tools/call`; a tool error comes back as a result flagged `isError`, so the agent can read it and correct itself.

The project, in order: `--project <folder>` (or `OPENWRITER_PROJECT`); the nearest `.ow` found walking up from the folder the agent starts in; the project open in the application (`workspace.json` in the app data). `--data <folder>` points to the application data. The server also reads the session saved by the app (`sessions.json`) to know which document the user has in front and which are open, so the tools that take a `document` default to the one in front.

**Which documents it reaches** (`authorizedDocument`): the documents of the project (a path relative to the root, or absolute inside the project folder, never in `.ow`, `.git` or `node_modules`); the documents linked to the project (`.ow/links.json`); and the documents open in OpenWriter, also outside the folder — opening one in the editor makes it part of the active workspace. Any other path is refused, whether absolute or reached with `..`. Folders, `read_project` and `search_documents` only concern the project folder (`projectPathInside`). Paths are compared with [path-compare.cjs](path-compare.cjs.md): case matters on Linux, not on Windows and macOS. The application enforces the same rule on the requests that arrive through the bridge.

Read tools: `project_info` (also lists the linked documents and those open outside the project), `get_context`, `list_skills`, `get_skill`, `read_project` (the whole tree in one call, with depth and entry limits), `list_documents`, `read_document` (in chunks; the saved file), `read_open_document` (what the user sees now: unsaved changes and edits waiting for review; through the bridge), `search_documents`, `list_notes`, `list_bookmarks`, `list_memory`.

Write tools (`WRITE_TOOLS`, absent with `--read-only`): `add_note` (a remark, or a suggestion when a `replacement` is given), `suggest_insertion`, `update_note`, `add_bookmark`, `update_bookmark`; `create_file` and `create_folder`, which use the same file tools as the internal assistant ([project-tools.cjs](project-tools.cjs.md)): inside the project folder only, never in `.ow`, `.git` or `node_modules`, `.md` or `.txt` documents, never overwriting an existing file nor reusing the name of another document unless `allowSameName`, written straight to disk (a new file replaces nothing); and, through the bridge, `replace_text`, `insert_text` and `replace_document` on the live editor. Quotations for notes must be plain words, unique and within one paragraph or heading: the server reduces the document to the plain text of [markdown-plain.cjs](markdown-plain.cjs.md), the same the editor sees, and anchors them, failing with a clear message when the passage is not found or appears more than once. A bookmark link is a path relative to the project root, or a `file:///` address for a document outside the project (between Windows drives there is no relative path).
