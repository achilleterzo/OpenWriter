# electron/chat-store.cjs

Source: [`electron/chat-store.cjs`](../../../electron/chat-store.cjs)

Conversation store under `.ow/chat/`. Each conversation is a readable `<id>.json` file with id (chronologically sortable: timestamp + random suffix), title (max 200 chars, fallback "New conversation"), timestamps, `parentId`/`branchedAt` branching metadata, `contextFrom` links to other conversations, `skillOverrides` (`add`/`remove` lists of writing-skill ids relative to the project defaults), `passages` (up to 10 document passages under discussion, `{ text, title, filePath }`, text max 20,000 chars), and a message log (all writes atomic).

Message roles: `user`, `assistant`, `tool` (a tool result named by `name`, answering the `toolCall` of the previous assistant message). Content up to 200,000 chars per message; messages preserve timestamps, error flags, model `thinking`, `toolCall` {name, arguments}, user `attachment` {label, detail, noteId, source, agent} — `source: 'mcp'` and `agent` mark a request that came from an external agent through the MCP server, so it is not mistaken for a message of the user — assistant `nextPrompt` hints, assistant `usage` {input, output} token counts, `images` references, and user `files` references {id, mime, label, size} to attached PDFs. Attachment payloads live in `.ow/chat/attachments/` as PNG/JPG/PDF files referenced by id and MIME type, and are named after the SHA-256 of their content, so the same image looked at twice (or attached again) is a single file.

Operations: `list` (summaries, newest update first; unreadable files are skipped), `get`, `create`, `save`, `remove` (also deleting the attachments no longer referenced by any conversation), `copyTo(id, targetProject)` (copies a conversation and the attachments it uses into another project's chat, to carry it on there), `setQueue`, `ensureDirectory`, `saveAttachment`, `getAttachment`. Conversation ids are validated (`[A-Za-z0-9_-]{1,80}`).

`sweepAttachments` drops the attachments no conversation cites any more, as happens when a chat is edited or truncated or after an older version; files younger than 10 minutes are left alone, since they may belong to a conversation not saved yet, and nothing is removed when a conversation file cannot be read. `remove` looks first for the attachments of the conversation being deleted and keeps the ones another conversation still cites, then runs the sweep, so deleting a chat never takes a file a branch still uses.
An assistant message can carry `interrupted: true` (the user stopped it half way); it is kept when saved and makes the turn resumable ([chatResume.js](../src/lib/chatResume.js.md)).

**The queue of a conversation.** A message written while the assistant is working waits in `queue` (at most 20 entries of `{ id, text, now }`, `now` for the ones sent with Ctrl/Cmd+Enter), and it survives an abrupt stop. It is written only by `setQueue(id, queue)`, which touches neither the rest of the conversation nor `updatedAt` (so the list of conversations is not reordered): a save of the conversation, even one made with a stale copy in hand, leaves on disk the queue that is already there.
