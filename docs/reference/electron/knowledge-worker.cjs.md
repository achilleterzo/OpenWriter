# electron/knowledge-worker.cjs

Source: [`electron/knowledge-worker.cjs`](../../../electron/knowledge-worker.cjs)

The worker thread that owns the search index, so that reading files and indexing never block the interface. `workerData` is `{ file, hiddenDirectories }`. It answers requests `{ id, op, ...}` with `{ id, result }` or `{ id, error }`; operations: `sync` (full scan), `paths` (update given paths), `search`, `stats`, `clear`, `rebuild` (clear the project and scan again), `semantic` (configure the search by meaning: `{ directory, projects, model, purge }`), `semanticStatus`, `close`. The logic is in [knowledge-index.cjs](knowledge-index.cjs.md) and [knowledge-sync.cjs](knowledge-sync.cjs.md); the main process talks to it through [knowledge-service.cjs](knowledge-service.cjs.md).

**Vectors**: if a project asked for the search by meaning and a model is installed, the worker is configured (`semantic`: `{ device, model, directory, projects, purge }`) with the **device** in use: `'cpu'` (the embedder runs in a thread of its own, [semantic-embedder-worker.cjs](semantic-embedder-worker.cjs.md)) or `'gpu'` (WebGPU only exists in Chromium, so the worker asks the main process for the vectors with `{ call, op: 'gpu-embed' }` messages that come back as `{ call, result | error }`, see [gpu-context.cjs](gpu-context.cjs.md)). After every `sync`, `paths`, `rebuild` and `semantic` it computes in the background the vectors that the model in use still lacks for the configured projects (the open project, its reference folders and the other shared projects): 8 passages per batch on the CPU, 32 on the GPU; changes that arrive while it runs are picked up in the same pass, and vectors computed for a model that is no longer the active one are discarded. Then it prunes the orphans. `search` with `options.semantic` embeds the question (`query: `) with the same model and passes `queryVector` and `model` to the index. `purge` lists models whose vectors to drop (their pack was removed). Any failure (missing or broken model, a graphics card that does not answer, memory) stops at `semanticStatus().error` and is also reported to the main process as an event `semantic-error` `{ device, model, error }`: the main process can switch device (a GPU failure falls back to the CPU). The search by words keeps working.
