# electron/gpu-embedder

Source: [`electron/gpu-embedder/`](../../../../electron/gpu-embedder/)

The page of the WebGPU context: a hidden Chromium window, opened by [gpu-context.cjs](../gpu-context.cjs.md), that computes the vectors of the embedding model on the graphics card with `onnxruntime-web` (WebGPU backend). WebGPU exists only inside Chromium, not in the threads of Node, so the work cannot happen in the main process or in the index worker; the window loads the fp16 model of the GPU pack ([semantic-pack.cjs](../semantic-pack.cjs.md)) and exchanges messages with the main process through its own preload.

- `index.html`: an empty page whose only content is `<script type="module" src="./page.mjs">`.
- `preload.cjs`: the bridge, exposed as `window.owEmbedder`, with two functions only — `onRequest(callback)`, which subscribes to `embed:request` and passes the message, and `reply(id, payload)`, which answers on `embed:reply`. The page receives requests and answers them, nothing else.
- `page.mjs`, the page itself, does the same as the CPU path of [semantic-embedder.cjs](../semantic-embedder.cjs.md), with the fp16 model: the E5 prefix (`query: ` / `passage: `), the tokeniser of the pack, the mean over the real tokens, the normalisation. Its limits are `MAX_TOKENS` (512, the last token kept when the text is longer) and `MAX_CHARS` (4,000 characters, cut before tokenising: a huge passage would overflow the stack).
- The model and the runtime are fetched from the pack served by the context: `pack/tokenizer.json`, `pack/tokenizer_config.json`, `pack/model.onnx`, `pack/ort.webgpu.bundle.min.mjs` (imported dynamically) and the asyncify WebAssembly files (`ort-wasm-simd-threaded.asyncify.mjs` / `.wasm`, resolved through `import.meta.url`). `ort.env.wasm.numThreads` is 1 — without cross-origin isolation there are no shared threads, and the GPU does the work — `ort.env.logLevel` is `error`, and the requested adapter preference is passed to `ort.env.webgpu.powerPreference`.
- Adapters: `power` is `'high-performance'` (dedicated card), `'low-power'` (integrated) or `'auto'` (the system chooses); `adapterInfo` reports `webgpu`, `vendor`, `architecture`, `device`, `description` and whether the adapter supports `shader-f16`. Since WebGPU does not enumerate the cards, `listAdapters` asks for both preferences, removes the duplicates by vendor/architecture/device/description and marks the one the system picks without preferences as `isDefault`.
- Operations, one at a time (a promise chain: the runtime runs a single session): `probe` returns the adapter information and the list of adapters; `embed` returns the vectors of the texts; `load` loads the model and answers `{ loaded: true }`; `release` drops the session. An unknown operation answers with an error. A failure is answered as `{ error: message }`, never thrown across the bridge. When the page starts it sends `reply(0, { ready: true })`, which is what makes the context consider it ready.
- `embed` builds `input_ids`, `attention_mask` and `token_type_ids` as `BigInt64Array` tensors padded to the longest text (`PAD_ID` 1), runs the session, converts a `Uint16Array` output from float16 to float32 (`halfToFloat`) and averages the hidden states over the masked tokens, normalising each vector. The tensors and the output are disposed after use.
