# electron/mcp-bridge.cjs

Source: [`electron/mcp-bridge.cjs`](../../../electron/mcp-bridge.cjs)

The bridge between the MCP server ([mcp-server.cjs](mcp-server.cjs.md), another process started by the agent) and the running application: it is what lets an agent change the documents open in the editor, so that the changes arrive as edits to review (accept/reject) instead of touching the file, and what lets it open a project or a document in the application or hand a task to the built-in assistant.

The application listens only on `127.0.0.1`, on a random port, and writes the port and a token in `mcp-bridge.json` in its data folder (readable by the user only; removed on exit if it is still its own). The MCP server reads that file and calls `POST /call` with the token. Each request goes to the interface (renderer), which runs it ([mcpRequests.js](../src/lib/mcpRequests.js.md)) and answers; requests are served one at a time, so two edits of the same document never overlap.

What it accepts: only the tools in `ALLOWED` (`read_open_document`, `replace_text`, `insert_text`, `replace_document`, `open_document`, `open_project`, `ask_agent`, `save_web_reference`, `refresh_web_reference` (web pages saved as context, see [web-references.cjs](web-references.cjs.md)), `dirty_documents`, which returns the unsaved text of the documents open in the editor so that the server's search can use it instead of the older files on disk, and `search_knowledge`); only for the project open in the application (another project is refused), except `open_project`, which is the tool that changes it and needs no project to be open; only while editing by agents is on (preference `openwriter.mcpEdit`, Settings → Agents (MCP)), except the *local tools* (`localTools`, only `search_knowledge`): the app runs them itself in the main process (they do not go through the interface), they only read, so they work even with editing off and with no window, and they do **not** depend on the project open in the app: they receive the project the agent works in (or none) and decide by themselves (the other tools are still refused for a project that is not the open one). It refuses requests with a wrong or missing token (401), with an `Origin` header (a web page) or a `Host` other than its own address (DNS rebinding) (403), and bodies over 8 MB. If the window stops responding, the pending requests fail.

**With more than one window** the project that counts is the one the agent names in its request, when a window shows it ([window-context.cjs](window-context.cjs.md), [document-owners.cjs](document-owners.cjs.md)); otherwise the project of the window in front is used. `replace_text`, `insert_text` and the other edits therefore land in the window that has that project open, not necessarily the last one used.

`createMcpBridge({ directory, getWindow, getProjectPath, isEnabled, localTools })` returns `{ start, stop, answer, rejectAll, bridgeFile }`.


`open_workspace` is a local tool too (it changes the app's state, not a document: valid with the agents' edits turned off). The request carries the `granted` projects of the agent, which reach the local tools in their context ([workspaces-store.cjs](workspaces-store.cjs.md)).
